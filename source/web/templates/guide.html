사용 흐름

  1. 신규 공지 가져오기대시보드 또는 보안 공지 화면에서 기간을 정하고 실행합니다. GitHub 수집 → 중복 확인 → Notion 저장 순서로 진행됩니다.

  3. 결과 확인분석 결과 · 공지 분석 · 취약 근거 화면에서 판정 결과와 근거를 확인합니다.

{# 4. 공지 수집 #}

공지 수집

시작일 · 종료일을 지정하고 신규 공지 가져오기를 누르면 수집이 시작됩니다. 화면을 이동해도 작업은 계속됩니다.

  • 기간은 GitHub 게시일(UTC) 기준이며 양 끝 날짜를 포함합니다. 기본값은 오늘을 포함한 최근 7일입니다.
  • 해당 기간의 공지를 갱신일 내림차순으로 최대 100건 가져옵니다.
  • 진행 중에는 수집 · 중복 확인 · 저장 단계와 수집 · 제외 · 저장 · 실패 건수를 표시합니다.
  • GitHub 요청 실패와 "정상 응답 0건"을 구분해 표시합니다. 일부 저장에 실패하면 같은 기간으로 다시 실행할 수 있습니다.
  • 수집이 끝나면 패키지 취약도 판정은 이어서 분석 실행으로 진행합니다.

Notion 중복 확인 기준

이미 저장된 공지는 (id, published_at)을 키로 찾습니다. 같은 기간을 여러 번 수집해도 중복 행이 생기지 않습니다.

Notion 상태처리
같은 공지가 없음새 행으로 저장
같은 공지가 있고 updated_at도 같음이미 저장된 공지로 보고 제외
같은 공지가 있고 updated_at이 다름GitHub에서 갱신된 공지로 보고 기존 행을 수정
같은 공지가 여러 행으로 저장되어 있음한 행만 남기고 나머지는 Notion 휴지통으로 이동
공지 ID가 없음식별할 수 없어 제외

Notion 조회에 실패하면 중복 적재를 막기 위해 저장을 진행하지 않습니다. Notion은 롤백을 지원하지 않으므로, 도중에 실패해도 이미 저장된 행은 유지됩니다.

{# 5. 취약도 분석 #}

취약도 분석

분석 실행은 Notion에 저장된 전체 공지와 서비스 패키지를 비교하고, 판정한 취약도를 Notion에 저장합니다. 진행 중에는 조회 → 판정 → 저장 단계와 저장 건수를 확인할 수 있으며, 실행 중 다시 요청하면 기존 작업 상태를 보여줍니다.

판정 상황저장 방식
취약점이 여러 개 일치critical > high > medium > low 중 가장 높은 값을 패키지별로 한 번 저장
버전 · 범위를 비교할 수 없음확인된 취약점이 없으면 unknown(알 수 없음)으로 저장
확인된 취약점과 판정 불가 공지가 함께 있음확인된 최고 심각도 유지
모든 비교가 불일치기존 값을 자동으로 safe로 되돌리지 않음
  • 버전 비교는 숫자와 점으로 된 버전(1.2.3)과 쉼표로 연결한 비교 조건(>= 1.0, < 2.0)을 지원합니다.
  • 분석 결과는 필터를 적용한 뒤 50개씩 표시합니다. 필터: all, critical, high, medium, low, safe, unknown
  • 취약 근거 화면은 저장된 데이터를 다시 비교해 근거만 보여주며, Notion 데이터를 수정하지 않습니다.
{# 6. 공지 통계와 데이터 갱신 #}

공지 통계 · 데이터 갱신

공지 분석은 저장된 공지의 심각도 분포, 생태계별 공지 수, 게시 추이, 공지가 많은 패키지 상위 10개를 보여줍니다. 기간은 게시일(UTC) 기준이며 비워두면 전체 기간입니다.

조회한 데이터는 서버에서 60초간 재사용합니다. 이후 접속하면 기존 데이터를 먼저 보여주고 백그라운드에서 갱신합니다. 최신 데이터 새로고침은 Notion 데이터를 다시 읽는 기능이며, GitHub 수집은 하지 않습니다.

화면 상태동작
처음 불러오는 중로딩 안내를 표시하고 준비되면 자동으로 다시 표시
기존 데이터 갱신 중마지막으로 성공한 결과를 먼저 표시
최신 조회 실패이전 데이터를 유지하고 실패 안내와 데이터 확인 시각 표시
조회할 수 없는 값—로 표시해 실제 빈 데이터와 구분
{# 7. Slack 알림 #}

Slack 알림

SLACK_WEBHOOK_URL에 연결된 채널로 알림을 보냅니다. 같은 오류는 한 번만 알리고, 토큰 · 웹훅 등 비밀 값은 가려서 전송합니다.

상황알림 내용
공지 수집 · Notion 적재 완료기간, 수집 · 생성 · 수정 · 제외 · 실패 건수와 실패 사유(최대 5건)
취약도 분석 · Notion 반영 완료분석 범위, 공지 · 검사 패키지 · 취약점 일치 · 영향 패키지 · 판정 불가 건수
작업 오류GitHub 수집 실패, Notion 연결 · 조회 · 저장 실패, 설정 로딩 오류
웹 · 서버 오류처리되지 않은 예외, HTTP 5xx, 백그라운드 작업 예외

GitHub 요청이 일시적으로 실패해 재시도하는 동안에는 알림을 보내지 않고, 최종 실패만 알립니다.

{# 8. 실행과 설정 #}

실행 · 설정

Python 3.10 이상이 필요합니다. 프로젝트 루트에서 의존성을 설치하고 .env를 준비한 뒤 대시보드를 실행합니다.

python -m pip install -r requirements.txt
python -m flask --app source.web.app run

실행 후 http://127.0.0.1:5000에 접속합니다. 서버를 시작하는 것만으로는 공지 수집이나 분석이 실행되지 않습니다.

환경변수 (.env)
환경변수용도
GITHUB_TOKENGitHub API 인증 (설정 시 요청 제한 완화)
NOTION_TOKENNotion 조회 · 저장 인증
NOTION_ADVISORIES_DATA_SOURCE_ID보안 공지 데이터 소스
NOTION_SERVICE_DATA_SOURCE_ID관리 서비스 데이터 소스
NOTION_SERVICE_PACKAGE_DATA_SOURCE_ID서비스 패키지 · 취약도 데이터 소스
SLACK_WEBHOOK_URL작업 · 오류 알림을 받을 Slack 웹훅
NOTION_PARENT_PAGE_IDNotion 데이터베이스를 만들 부모 페이지

Notion 조회에는 데이터베이스 ID가 아닌 데이터 소스 ID를 사용합니다. .env는 Git에 올리지 않습니다.

운영 시 참고 사항
  • 수집 · 분석 상태와 최근 실행 기록은 서버 메모리에 보관합니다. 현재 구조는 단일 서버 프로세스용입니다.
  • 서버를 재시작하면 진행 중인 작업이 중단되고 실행 기록이 초기화됩니다. Notion에 이미 저장된 데이터는 유지됩니다.
  • Notion 요청은 최소 0.5초 간격으로 보내고, 일시적인 오류는 최대 3회까지 다시 시도합니다.
